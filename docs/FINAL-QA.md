## P1 fixed

### QA-P1-01 — PDP mobile identity below first viewport

**Before:** At 390 × 844, gallery + thumbnails + fit cue consumed the first viewport; price and sticky Add to cart were visible before the product name. This conflicted with the Design Contract mobile order `gallery → title + price → key facts` and weakened the 5-second product-identity test.

**Root owner:** `css/detail.css` mobile gallery sizing/composition.

**Fix:** Reduced mobile gallery depth while retaining one primary room image + two evidence thumbnails; tightened media evidence spacing and product-stage gap. The product title, price and description now enter the first viewport after the gallery/context cue.

**After:** Rendered evidence shows `Miro Lounge Chair` + `$320` within 390 × 844 while retaining useful scale/material imagery.

## Visual / composition result

- Home: image-led orientation + discovery paths.

Cross-page top captures do not collapse into one universal hero/template family. Shared recognition comes from warm paper/canvas surfaces, Newsreader + DM Sans hierarchy, architectural hairlines/frames, catalogue/object indexing and restrained clay accents.

## Brand / header / CTA result

- Logo/wordmark readable in inspected top, scrolled and mobile navigation states.
- Active navigation remains visible.
- Primary actions retain strong ink/paper contrast; clay remains focal rather than becoming a universal fill.
- Mobile menu and search overlay retain the same brand grammar.

## Responsive result

- No horizontal overflow detected in captured 390, 768, 1024, 1440 and representative 1920 evidence.
- Home intentionally recomposes from split editorial hero to media → copy/discovery.
- Collection keeps user scope/refinement legible at tablet/mobile widths.
- PDP moves from desktop media+decision split to a compact mobile media sequence followed by product identity/evidence.
- Touch-oriented menu/filter/search surfaces remain usable in inspected states.

## UX / journey result

- Home exposes object / room / search finding routes early.
- PLP preserves result scope and applied-filter context and keeps filtering/sorting task-specific.
- PDP exposes fit, dimensions, finish, availability and arrival around the purchase decision.
- Consultation remains a secondary path for uncertainty rather than competing with the primary purchase path.
- Cart/checkout preserve editability and prototype payment truth.

## Content / system reality result

- Search, filtering, cart and wishlist remain real within the static client-side dataset/browser storage.
- Checkout remains explicitly simulated/partial; no real-payment claim is introduced.
- Contact remains prototype/simulated; no guaranteed CRM-delivery claim is introduced.
- Unsupported owner-review/social-proof copy was removed from PDP during implementation.

## Accessibility / interaction scope

- Focus-visible and reduced-motion support remain in shared/route styles.
- Native controls/labels are preserved for primary forms and filtering controls.
- Menu, search, filter and purchase states were render-smoked.
- This QA does **not** claim formal WCAG conformance or a complete screen-reader audit.
