# LuxRoom Visual Regression Plan

## Purpose
Protect the Quiet Architectural Commerce redesign from both rendered regressions and design-system drift.

## Source of visual truth
1. `docs/DESIGN-CONTRACT.md`
2. `docs/design-reference-benchmark.md`
3. Logo-derived brand evidence and semantic tokens in `css/design-system.css`
4. Representative rendered evidence generated by `.github/workflows/visual-qa.yml`

## Representative coverage

### Primary routes
- Home: `index.html`
- Collection / PLP: `products.html`
- Product detail / PDP: `detail.html?product=1`
- Story: `about.html`
- Assisted conversion: `contact.html`
- Cart: `cart.html`
- Checkout: `checkout.html`

### Required state captures
- Home desktop top
- Home desktop scrolled header
- Home mobile top
- Home mobile menu open
- Collection desktop top
- Collection mobile top
- Collection mobile filters open
- PDP desktop top
- PDP mobile top
- PDP mobile lower/spec section

### Viewports
- Primary desktop evidence: 1440 × 1000
- Primary mobile evidence: 390 × 844
- Manual/intermediate risk checks before high-risk release: 768, 1024, and 1920 widths

## Stable capture rules
- Wait for network idle and local font readiness.
- Emulate `prefers-reduced-motion: reduce` for deterministic screenshots.
- Disable decorative animation duration during capture.
- Use repository assets and client-side static product data as-is.
- Do not accept new baselines automatically when a visual change is unintended.

## Drift assertions
Flag as regression when not intentionally approved:
- raw page-specific brand colors replacing semantic tokens;
- new rounded-card/shadow language that conflicts with architectural framing;
- universal hero/composition reuse across materially different primary page roles;
- loss of Room Frame / Clay Point / Object Index signatures;
- mobile becoming compressed/stacked desktop rather than task-specific recomposition;
- logo/nav/CTA losing contrast in top/scrolled/mobile states;
- furniture decision evidence (fit, dimensions, availability, arrival) moving away from purchase context;
- new override-pile CSS added instead of fixing the owning stylesheet/component.

## Severity
- P0: blocked navigation/conversion, unreadable critical content, severe interaction/accessibility failure.
- P1: major composition, brand, trust, responsive, hierarchy or system-reality defect.
- P2: noticeable craft drift that weakens polish/consistency.
- P3: optional preference.

## Review loop
`capture → cross-page contact sheet → macro audit → log P0/P1/P2 → fix root owner → recapture same routes/states → compare → update baseline intentionally`

## Release gate
A substantial visual release is not called visually passed unless the generated evidence has been opened/inspected and no actionable P0/P1/P2 remains within tested scope. Source/build/CI success alone is not a visual pass.
